# browser-use 14 天学习计划

> **目标读者**:具备 Python 异步编程基础(Pydantic v2、asyncio、type hints)并希望深入理解 browser-use 源码与扩展方式的工程师。
> **总投入**:14 天 × 4 小时 ≈ 56 小时
> **学习路径**:自顶向下 —— 先跑通最小例子,再分模块精读,最后动手扩展
> **前置准备**:
> - Python 3.11+
> - `uv` 包管理(项目用 uv 锁定依赖)
> - 至少一个可用的 LLM API key(OpenAI / Anthropic / BrowserUse Cloud 任一,推荐 `ChatBrowserUse` 入门最省事)
> - Chrome / Chromium 浏览器已安装

---

## 全局里程碑(每周验收)

| 周次 | 阶段 | 验收标准 | 对应 Day |
|------|------|----------|----------|
| W1 | 跑通 + 核心架构 | 能用 Agent 完成一个 5 步任务;能口述 EventBus + Watchdog 协作流程 | Day 1–6 |

| W3 | 输出 | 给开源仓库提一个 PR / 在本地仓库实现一个新工具 | Day 11–14 |

## 附录 C · 速查 · 调试清单(任务跑挂时按此排查)

1. **LLM 返回非预期结构** → 看 `agent.history.last_model_output()`,确认是 prompt 问题还是 schema 问题
2. **Click 没点中** → 打开 `dom_watchdog` 调试日志,看 selector_map 索引 → 元素 rect 坐标
3. **页面没加载完** → 调大 `wait_for_load_state`、看 `screenshot_watchdog` 实际截图
4. **Browser 卡死** → `BrowserSession.is_cdp_connected` 是否为 False,看 `crash_watchdog` 日志
5. **Token 超限** → 看 `message_manager` 的 `state.message_history_tokens`,启用 `use_thinking=False` 或 `flash_mode=True`
6. **Action 没执行** → `registry.registry.actions` 字典里有没有?被 `exclude_actions` 排除了吗?
7. **Chrome 启动失败** → `local_browser_watchdog` 日志,检查 `executable_path` / `channel` / `headless`
8. **MCP server 连不上** → 单独跑 `uvx @modelcontextprotocol/server-fetch`,再让 browser-use 接
