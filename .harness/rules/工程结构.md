# 工程结构规范

## 项目结构

优先使用 `ls -l`和 `tree` 命令查看目录结构

## 文件命名规范

- Python 文件：使用小写下划线命名法 (`service.py`, `dom_service.py`)
- Pydantic 模型文件：`views.py`
- 事件定义文件：`events.py`
- 测试文件：`test_*.py`
- 配置目录：`*.d/` 或 `*/`

## Pydantic 模型组织

```python
# views.py - 数据模型
class AgentView(BaseModel):
    id: str = Field(default_factory=uuid7str)
    name: str

# events.py - 事件定义
class AgentEvent(BaseModel):
    event_type: str
    timestamp: datetime
```

## 模块分层架构

```
表现层 (Interface)
    ↓
应用层 (Application/Use Cases)
    ↓
领域层 (Domain)
    ↓
基础设施层 (Infrastructure)
```

### 各层职责

| 层级 | 目录 | 职责 |
|------|------|------|
| 表现层 | `agent/` | 接收任务、返回结果、编排流程 |
| 应用层 | `tools/` | 定义工具能力、协调调用 |
| 领域层 | `dom/`, `browser/` | 核心业务逻辑、状态管理 |
| 基础设施层 | `llm/`, `mcp/` | 外部依赖适配、协议实现 |

## 核心约束

- **ID 生成**：使用 `uuid7str` 生成唯一 ID
- **超时设置**：外部服务调用必须设置超时和降级
- **错误处理**：所有外部调用必须 try-catch 处理

## 上下文分层加载策略

### L1 - 会话常驻层（Always Loaded）
- Agent 定义文件
- 三份 Rules 文件

### L2 - 阶段触发层（Phase-triggered）
- 需求分析阶段：加载 `request-analysis` Skill
- 编码阶段：加载 `coding-skill` 和分层编码 Spec
- 评审阶段：加载 `expert-reviewer`

### L3 - 按需查询层（On-demand）
- Wiki 知识库中的业务文档
- 按任务需要自主查阅
