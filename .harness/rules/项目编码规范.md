# 项目编码规范

## Python 代码规范

### 版本要求
- Python >= 3.11
- 使用 `async`/`await` 异步编程

### 类型提示
变量类型、返回值类型完整
```python
# 正确
def process(user_id: str) -> list[dict[str, Any]]:
    ...

# 错误
def process(user_id) -> List[Dict]:
    ...
```

### 类型规范
| 场景 | 正确写法 | 错误写法 |
|------|----------|----------|
| 可选字符串 | `str \| None` | `Optional[str]` |
| 列表 | `list[str]` | `List[str]` |
| 字典 | `dict[str, Any]` | `Dict[str, Any]` |
| 集合 | `set[int]` | `Set[int]` |

class PriceField(BaseModel):

## 日志规范

### 日志方法命名
- 前缀 `_log_` 用于日志方法
- 将日志逻辑与主逻辑分离

```python
class AgentService:
    def _log_request(self, request: Request) -> None:
        logger.info(f"Request: {request.action}")

    async def execute(self, request: Request) -> Response:
        self._log_request(request)
        # 主逻辑
```

### 日志级别
- DEBUG: 调试信息
- INFO: 一般信息
- WARNING: 警告
- ERROR: 错误

## 前端表单校验规范

### 校验时机
| 时机 | 场景 | 示例 |
|------|------|------|
| 提交时 | 全量校验所有字段 | 确认计划前校验所有用例 |
| 保存前 | 校验即将持久化的数据 | 保存变量集行前校验空值 |
| 实时 | 格式类校验（可选） | URL 格式、变量名格式 |

### 必须校验的场景

#### 1. 空集合防护
提交前必须检查列表/集合是否为空，禁止提交空数据：
```typescript
// 正确
if (items.length === 0) {
  setError("至少需要一条数据");
  return;
}

// 错误：直接遍历校验，空数组会跳过循环导致校验通过
for (const item of items) { validate(item); }
```

#### 2. 必填字段
所有标记 `*` 的字段必须校验非空（trim 后）：
```typescript
const emptyName = !value.trim();
```

#### 3. 格式校验
- URL：正则 + 端口范围 1-65535
- 变量名：`/^[a-zA-Z_][a-zA-Z0-9_]*$/`，长度限制
- 邮箱、手机号等：使用成熟正则或 zod schema

```typescript
// URL 端口校验示例
function isValidPort(portStr: string): boolean {
  const n = Number(portStr);
  return Number.isInteger(n) && n >= 1 && n <= 65535;
}
```

#### 4. 子项完整性
父级提交时必须递归校验所有子项：
```typescript
// 正确：校验每个步骤的操作描述非空
const emptySteps = steps
  .map((s, i) => (!s.description.trim() ? i : -1))
  .filter((i) => i >= 0);

// 错误：只校验步骤数量，不校验内容
if (steps.length > 0) { /* 通过 */ }
```

#### 5. 关联数据一致性
引用关系两端必须同时校验：
```typescript
// 步骤引用的变量 vs 变量集定义的列
const referenced = extractVarsFromSteps(steps);
const defined = new Set(varColumns);
const missing = [...referenced].filter((v) => !defined.has(v));
const extra = [...defined].filter((v) => !referenced.has(v));
```

#### 6. 缓存数据新鲜度
校验前必须确保依赖数据已加载，不能依赖可能为空的本地缓存：
```typescript
// 正确：校验前加载未获取的数据
const unloaded = items.filter((i) => cache[i.id] === undefined);
if (unloaded.length > 0) {
  await Promise.all(unloaded.map((i) => loadData(i.id)));
}

// 错误：直接用缓存，未加载的项被当作空数组
const data = cache[id] ?? [];
```

#### 7. 部分空值拦截
保存行数据时，不仅拦截全空行，也要拦截部分列为空的行：
```typescript
// 正确：逐行逐值检查
const partialEmpty = rows.filter((row) =>
  Object.values(row).some((v) => !v.trim())
);
if (partialEmpty.length > 0) {
  setError("存在未填写完整的行");
  return;
}
```

#### 8. 前置条件防护
操作依赖的上下文（如 sessionId、parentId）必须在执行前校验：
```typescript
// 正确：操作前检查前置条件
if (!sessionId) {
  setError("会话无效，无法执行操作");
  return;
}
await confirmPlan(planId);
await resumeSession(sessionId);
```

### 校验结果展示
- 错误信息精确到具体字段和行号
- 校验未通过的条目红色高亮标记
- 提供"关闭"按钮允许用户清除错误提示
- 多条错误换行展示，不截断

### 数据同步规则
- 重命名操作必须同步更新所有引用该名称的缓存数据
- 删除操作必须级联清理关联的本地状态
- 本地编辑使用 localState 隔离，避免父组件重渲染导致数据丢失
